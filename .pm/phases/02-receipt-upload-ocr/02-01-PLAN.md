# Phase 2: Receipt Upload & OCR

## Objective

**Goal:** Build the core receipt capture pipeline: upload an image, extract structured data via Google Cloud Vision OCR, save to database, and allow manual correction.

**Purpose:** This is the core value prop — snap a photo, get spending data. Everything else builds on receipts existing in the database.

**Output:** Receipts list page, upload flow with OCR extraction, receipt detail view with editable fields.

## Acceptance Criteria

- [ ] **AC-1: Image Upload** — User can upload a receipt image via drag-and-drop or file picker; image is stored in Supabase Storage and URL saved to the receipt record
- [ ] **AC-2: OCR Extraction** — Google Cloud Vision TEXT_DETECTION extracts raw text; parsing logic extracts merchant, date, total, tax, and line items with >70% accuracy on clear receipts
- [ ] **AC-3: Receipt Creation** — After OCR, a pre-filled form shows extracted data; user can correct fields and save; receipt + items are persisted to database
- [ ] **AC-4: Receipt List** — `/receipts` page shows all user receipts sorted by date (newest first) with merchant, date, total, and category displayed
- [ ] **AC-5: Receipt Detail** — `/receipts/[id]` shows full receipt with image, all fields, and line items; fields are editable inline
- [ ] **AC-6: Tests Pass** — OCR parsing tests pass with sample receipt text fixtures; API route tests pass

## Tasks

### Task 1: Upload & OCR Pipeline

| Field | Value |
|-------|-------|
| Discipline | fullstack |
| Status | pending |
| Files | `src/app/api/ocr/route.ts`, `src/app/api/receipts/route.ts`, `src/app/api/receipts/[id]/route.ts`, `src/lib/ocr/parse.ts`, `src/lib/ocr/extract-fields.ts`, `src/lib/storage.ts` |

**What to do:**
- Create Supabase Storage bucket `receipts` with RLS (user can only access own files)
- Build storage helper: upload image, return public URL
- Build OCR API route (`POST /api/ocr`): accepts image file, calls Google Cloud Vision TEXT_DETECTION, returns raw text + extracted fields
- Build field extraction logic (`extract-fields.ts`): parse raw OCR text to extract merchant (first line heuristic), date (regex patterns for common date formats), total (largest amount or "TOTAL" line), tax (line containing "TAX"/"GST"/"VAT"), line items (lines with price pattern)
- Build receipts API routes: `POST /api/receipts` (create with items), `GET /api/receipts` (list for user), `GET /api/receipts/[id]` (single), `PATCH /api/receipts/[id]` (update fields)
- Write tests with sample OCR text fixtures (at least 3 receipt formats)

**Verification:** `curl POST /api/ocr` with a test image → returns extracted fields; `npm run test` passes

**Done when:** AC-2, AC-6

## Boundaries

### Do Not Change
- Auth system from Phase 1
- Database schema (use existing tables)
- Sidebar navigation structure

### Scope Limits
- No category management UI (Phase 3) — use existing seeded categories in dropdown
- No search or filtering (Phase 3)
- No batch upload — single receipt at a time
- OCR is best-effort extraction — user corrects mistakes manually
