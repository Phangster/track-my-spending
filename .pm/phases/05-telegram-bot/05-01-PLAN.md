# Phase 5: Telegram Bot

## Objective

**Goal:** Build a Telegram bot that lets users photograph receipts from their phone, link to their web account, and process receipts through the existing OCR pipeline.

**Purpose:** Mobile receipt capture is the primary use case — users buy something, snap a photo in Telegram immediately, and it's tracked. No need to open the web app.

**Output:** Telegram bot with account linking, photo receipt processing, and a Cloud Run-ready Docker container.

## Acceptance Criteria

- [ ] **AC-1: Account Linking** — User generates a 6-digit code in web Settings; sends code to Telegram bot via `/link`; accounts are linked; code expires after 10 minutes
- [ ] **AC-2: Photo Receipt Processing** — Linked user sends a photo to the bot; bot calls OCR pipeline, creates receipt in database; bot replies with extracted merchant, total, and a "View receipt" link
- [ ] **AC-3: Bot Commands** — `/start` shows welcome message; `/link <code>` links account; `/recent` shows last 5 receipts with merchant and total; `/help` lists available commands
- [ ] **AC-4: Dockerized** — Bot runs in a Docker container with a webhook endpoint; `docker build && docker run` works locally
- [ ] **AC-5: Tests Pass** — Account linking flow tests pass; bot command handler tests pass

**What to do:**
- Create migration: add `telegram_chat_id` (bigint, unique, nullable) to a `telegram_links` table with `user_id` FK; add `link_codes` table (code text, user_id, expires_at timestamp, used boolean)
- Build web-side link code API (`POST /api/telegram/link`): generates random 6-digit code, stores with 10-min expiry, returns code
- Build Settings page: "Link Telegram" section showing current link status; "Generate Code" button; displays code with countdown timer
- Build bot entry point (`bot/main.ts`): Express server receiving webhook POST from Telegram; routes updates to command handlers
- Build Telegram API helper (`bot/lib/telegram.ts`): thin wrapper around `sendMessage`, `getFile` using raw fetch — no framework
- Build `/start` handler: welcome message explaining the bot and how to link
- Build `/link <code>` handler: validates code against `link_codes` table (not expired, not used), creates `telegram_links` row, marks code used, replies with success
- Build `/recent` handler: fetches last 5 receipts for linked user, formats as text list
- Build `/help` handler: lists available commands

**Verification:** Generate code in web app → send `/link <code>` in Telegram → bot confirms → `/recent` shows receipts

## Boundaries

### Do Not Change
- Web app auth system
- Existing receipt/OCR API routes (bot uses its own Supabase client directly)
- Receipt UI in web app

### Scope Limits
- No inline keyboards or complex Telegram UI
- No receipt editing via Telegram — view only (edit in web app)
- No group chat support — private messages only
- No multi-photo or document upload — single photo per message
- Bot does not send proactive messages (no spending alerts)
