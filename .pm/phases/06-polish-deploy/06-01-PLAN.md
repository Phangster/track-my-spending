# Phase 6: Polish & Deploy

## Objective

**Goal:** Harden error handling, add loading/empty states, polish responsive design, and deploy the web app to Vercel and the Telegram bot to Cloud Run.

**Purpose:** Move from "works on localhost" to production-ready. Cover edge cases, make the UI feel complete, and ship.

**Output:** Deployed web app on Vercel, deployed bot on Cloud Run, polished UX across all pages.

## Acceptance Criteria

- [ ] **AC-1: Error Handling** — All pages have error boundaries; API errors show user-friendly messages; network failures are handled gracefully
- [ ] **AC-2: Loading & Empty States** — All data-fetching pages show skeleton loaders while loading; empty states with helpful CTAs (e.g., "No receipts yet — upload your first one")
- [ ] **AC-3: Responsive Design** — All pages work on mobile (375px+), tablet, and desktop; sidebar collapses; forms are usable on small screens
- [ ] **AC-4: Vercel Deployment** — Web app deployed to Vercel with environment variables configured; production build runs without errors
- [ ] **AC-5: Cloud Run Deployment** — Telegram bot deployed to Cloud Run; webhook URL set via Telegram API; bot responds in production
- [ ] **AC-6: Environment Config** — All secrets managed via environment variables; no hardcoded credentials; `.env.example` documents all required vars

## Boundaries

### Do Not Change
- Core feature logic (OCR parsing, categorization, recurring detection)
- Database schema
- API route signatures

### Scope Limits
- No custom domain setup (use Vercel default URL)
- No CI/CD pipeline beyond Cloud Build for bot
- No monitoring or alerting setup
- No performance optimization (lighthouse audit, etc.)
- No analytics integration
