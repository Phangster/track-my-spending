# Phase 3: Categories & Organization

## Objective

**Goal:** Enable users to manage custom categories with keyword-based auto-categorization, and find receipts through full-text search and multi-dimensional filtering.

**Purpose:** As receipt volume grows, users need to organize and find transactions quickly. Categories give spending structure; search and filters give retrieval speed.

**Output:** Categories management page, auto-categorization on receipt save, search bar, and filter panel on the receipts list.

## Acceptance Criteria

- [ ] **AC-1: Category CRUD** — User can create, edit, and delete custom categories with name, icon, color, and keyword list; deleting a category nulls `category_id` on associated receipts (not cascade delete)
- [ ] **AC-2: Auto-Categorization** — When a receipt is saved, if no category is manually selected, the system matches merchant name against category keywords and assigns the best match
- [ ] **AC-3: Full-Text Search** — Typing in the search bar filters receipts by merchant name or item names; results update as the user types (debounced)
- [ ] **AC-4: Multi-Dimensional Filtering** — Receipt list can be filtered by: date range, category (multi-select), and amount range (min/max); filters combine with AND logic
- [ ] **AC-5: Tests Pass** — Auto-categorization logic tests pass; API route tests pass

## Boundaries

### Do Not Change
- Receipt upload/OCR flow from Phase 2
- Auth system from Phase 1
- Database schema (categories table already exists from Phase 1 migration)

### Scope Limits
- No AI-based categorization — keyword substring matching only
- No bulk category assignment
- No saved/preset filter views
- Search is client-side filtering via API params, not Postgres full-text search (simple ilike is sufficient at this scale)
