# Phase 1: Foundation

## Objective

**Goal:** Scaffold the Next.js 15 application with Supabase authentication and database schema, delivering a working auth flow and protected app shell.

**Purpose:** Every subsequent phase depends on auth, database tables, and the app layout. This must be solid before building features.

**Output:** Working Next.js 15 app with login/signup, Google OAuth, protected routes, sidebar navigation, and database tables (receipts, receipt_items, categories) with RLS policies.

## Acceptance Criteria

- [ ] **AC-1: Project Setup** — Next.js 15 runs locally with TypeScript, Tailwind CSS, and App Router; `npm run dev` starts without errors
- [ ] **AC-2: Authentication** — Email/password signup and login work; Google OAuth redirects and completes; sessions persist across page reloads
- [ ] **AC-3: Database Schema** — Supabase migration creates `receipts`, `receipt_items`, and `categories` tables with RLS policies that restrict access to the owning user
- [ ] **AC-4: Protected Layout** — Unauthenticated users are redirected to `/login`; authenticated users see a sidebar with navigation links (Dashboard, Receipts, Categories, Settings)
- [ ] **AC-5: Tests Pass** — `npm run test` passes with coverage of auth flows and middleware

### Task 2: Database Schema & RLS

| Field | Value |
|-------|-------|
| Discipline | backend |
| Status | pending |
| Files | `supabase/migrations/001_initial_schema.sql` |

**What to do:**
- Create SQL migration with tables:
  - `categories`: id (uuid PK), user_id (uuid FK → auth.users), name (text), icon (text nullable), color (text nullable), keywords (text[] for auto-categorization), created_at, updated_at
  - `receipts`: id (uuid PK), user_id (uuid FK → auth.users), merchant (text), date (date), subtotal (numeric), tax (numeric), total (numeric), category_id (uuid FK → categories nullable), image_url (text nullable), notes (text nullable), created_at, updated_at
  - `receipt_items`: id (uuid PK), receipt_id (uuid FK → receipts ON DELETE CASCADE), name (text), quantity (numeric default 1), unit_price (numeric), total_price (numeric)
- Enable RLS on all three tables
- Create policies: users can only SELECT/INSERT/UPDATE/DELETE their own rows (WHERE user_id = auth.uid())
- Seed default categories: Groceries, Dining, Transport, Shopping, Health, Utilities, Entertainment, Other

**Verification:** Run migration in Supabase dashboard or CLI → verify tables exist → insert test row → confirm RLS blocks cross-user access

**Done when:** AC-3
