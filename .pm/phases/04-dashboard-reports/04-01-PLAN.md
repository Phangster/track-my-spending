# Phase 4: Dashboard & Reports

## Objective

**Goal:** Replace the placeholder dashboard with spending visualizations, period comparisons, recurring expense detection, and CSV export.

**Purpose:** Users need to understand their spending patterns at a glance. Charts and summaries turn raw receipt data into actionable insights.

**Output:** Dashboard with summary cards, Recharts charts, recurring expense detection, and CSV export endpoint.

## Acceptance Criteria

- [ ] **AC-1: Summary Cards** — Dashboard shows total spent, receipt count, and average transaction for the selected period; values update when period changes
- [ ] **AC-2: Category Breakdown** — Pie or bar chart shows spending by category for the selected period; clicking a category navigates to filtered receipt list
- [ ] **AC-3: Spending Trend** — Line chart shows daily/weekly/monthly spending over the selected period
- [ ] **AC-4: Period Comparison** — User can compare two periods side-by-side (e.g., this month vs last month) with delta percentages
- [ ] **AC-5: Recurring Detection** — System identifies recurring expenses (3+ receipts, same merchant, amounts within 10% tolerance) and displays them with frequency and average amount
- [ ] **AC-6: CSV Export** — User can download filtered receipt data as CSV with columns: date, merchant, category, subtotal, tax, total, items
- [ ] **AC-7: Tests Pass** — Recurring detection algorithm tests pass; dashboard API tests pass

### Task 2: Recurring Detection & CSV Export

| Field | Value |
|-------|-------|
| Discipline | fullstack |
| Status | pending |
| Files | `src/app/api/receipts/recurring/route.ts`, `src/app/api/receipts/export/route.ts`, `src/components/recurring-expenses.tsx`, `src/lib/recurring.ts` |

**What to do:**
- Build recurring detection logic (`recurring.ts`):
  - Group receipts by merchant name (case-insensitive)
  - For each merchant with 3+ receipts: check if amounts are within 10% tolerance of the median
  - Calculate frequency: average days between transactions
  - Return: merchant, count, average_amount, frequency_days, last_date
- Build recurring API route (`GET /api/receipts/recurring`): returns detected recurring expenses for the user
- Build recurring expenses component: table/card list showing merchant, frequency ("Weekly", "Monthly", etc.), average amount, last occurrence
- Build CSV export route (`GET /api/receipts/export`): accepts same filter params as receipt list (date range, category, amount, search); returns CSV with headers: Date, Merchant, Category, Subtotal, Tax, Total, Items
- Add export button to receipt list page (downloads CSV of current filtered view)
- Write tests for recurring detection with edge cases (exactly 3 receipts, amounts at 10% boundary, single merchant)

**Verification:** Create 4 receipts from same merchant with similar amounts → recurring detection identifies it; export filtered receipts → CSV downloads with correct data

**Done when:** AC-5, AC-6, AC-7
